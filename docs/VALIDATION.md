# 분리 작업 검증 기록 — 2026-10-28

## 통과

- 중지 상태 NAS 백업 복사본의 SQLite integrity_check=ok, foreign_key_check 오류 없음.
- 원본 SQLite → 로컬 PostgreSQL 17.6 이전 후 모든 테이블의 전체 행 및 이미지 바이너리 지문 일치.
- 계정 ID, 비밀번호 해시, 세션, 캐릭터, 이미지, 진행 상태, 친구 관계를 보존.
- PostgreSQL pg_dump → 별도 DB pg_restore 후 다시 원본 SQLite 전체 데이터와 일치.
- PostgreSQL 통합 검증을 포함한 서버 테스트 14개 통과.
- 프론트 전체 테스트 94개 통과.
- 프론트 및 서버 정적 분석 통과.
- 프론트 release 웹 빌드 통과, Dart API 실행 파일 컴파일 통과.
- Compose 설정 문법 검증 통과, 고정 Dart 이미지 태그 manifest 확인.

진행도 복구 테스트에서 장면 시작 안내가 중복되는 문제를 발견해, 장면 시작 시 재개 노드를
먼저 저장하도록 수정했다. 이전 SQLite의 시작 시 자동 데이터 삭제 정리는 명시적 옵션으로 바꿨다.

## 남은 운영 검증

- 이 PC의 Docker Desktop 엔진이 실행되지 않아 컨테이너 이미지 빌드와 Compose 전체 기동은 검증하지 못함.
- 실제 NAS에서 별도 폴더/포트로 새 구성 빌드 및 기동 검증 필요.
- 현재 운영 데이터에 대한 최종 최신 백업과 이전은 아직 수행하지 않음.
- NAS HTTPS 인증서 문제는 이번 코드 변경과 별개이며 아직 해결하지 않음.
- Private GitHub의 Deploy Key, NAS 작업 스케줄러의 일일 백업 등록은 실제 NAS에서 설정 필요.

NAS 운영 서버, 원본 DB, GitHub 저장소의 공개/비공개 설정은 변경하지 않았다.
DB 이전은 별도 로컬 테스트 인스턴스에서만 수행했다.

이미지와 플레이 상태는 데이터 보존을 위해 기존 저장 포맷을 유지한다.
PostgreSQL 조회용 뷰는 추가했으나 플레이 상태 전체를 별도 정규화 테이블로 다시 설계한 것은 아니다.
관련 운영 절차는 OPERATIONS.md를 참고한다.
